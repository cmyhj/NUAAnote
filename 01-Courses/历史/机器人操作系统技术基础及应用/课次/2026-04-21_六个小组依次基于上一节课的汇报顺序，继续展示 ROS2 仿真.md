## 要点详述

### 一、项目一：Godot + ROS2 机器人视觉预测仿真（00:57–07:15）

**背景与动机** [00:57–02:00]：团队此前在比赛中用实物机器人做视觉预测算法测试，需克服高温蚊虫、电池续航、场地供电等问题，开发效率低。为解决物理验证的高成本问题，选择在游戏引擎中搭建仿真环境。

**技术选型** [01:14–01:31]：采用 Godot 游戏引擎而非 Unity/虚幻引擎。Godot v4.4 之前仅支持 2D，更新后新增 3D 模式并具备较好的物理引擎。

**架构设计**：
1. **中间层** [02:19–02:37]：Godot 原生不支持 ROS 消息通信，团队开发了基于 rcl（ROS Communication Library）的中间件，底层调用 rclcpp，上层封装 GDScript 接口。
2. **感知层** [02:46–03:30]：接收 ROS image 话题与平台位姿数据 → 神经网络识别苹果等目标 → 坐标展开提取四个角点 → 利用 PnP 算法解算标靶（目标）相对于相机的空间位姿。标靶与相机中心的距离（如 700 mm）为已知参数 [04:03]。
3. **节点设计** [05:46–06:14]：在 Godot 场景树中拖入节点即可从 Godot 获取图像并通过 rcl 中间件发布；云台（PTZ）包含两个坐标变换关系：相机→云台中心、云台→车体。

**演示效果** [09:56–10:13]：实现了自动瞄准（auto-aiming）功能——右键锁定目标后，机器人自动跟住目标。

**分工** [11:04–12:42]：
- 搭建 rcl 中间件 + 整套流程调试
- 算法迁移与适配
- 云台/底盘/发射机构控制
- 标靶与机器人模型设计
- PPT 制作与内容整理

### 三、项目三：Xacro → Gazebo → SLAM 自主导航（14:23–23:11）

**项目概述** [14:23–14:37]：基于 ROS2 的小车仿真，学习目标为掌握 Xacro、物理仿真、机器人控制、SLAM 自主建图及 Rviz2 可视化调试。

**实现步骤**：
1. **模型优化** [14:48–14:59]：基于开源 URDF 小车模型，使用 Xacro 将常量（如 π、底盘边长等）封装为宏变量，组合编写 launch 文件。
2. **Gazebo 集成** [15:06–15:15]：将 Xacro 版的机器人模型显示在 Gazebo 中。
3. **仿真环境搭建** [15:22–15:30]：自主搭建地图，保存为 `.world` 文件。
4. **运动控制** [15:40–15:56]：使用 ros_control 节点，编写传动装置与控制器配置文件，为机器人关节添加传动与控制。
5. **可视化** [15:57–16:05]：在 Rviz2 中使用里程计插件显示机器人运动朝向。
6. **雷达仿真与 SLAM** [16:06–16:34]：激光雷达数据仿真显示，基于 gmapping 算法实现 SLAM 建图，再通过导航完成路径规划。

**演示** [21:28–22:21]：在 Rviz2 中设置目标点，机器人自主导航到达；可另开终端保存地图至本地文件夹。

**分工** [22:59–23:41]：
- SLAM 与 Rviz2 可视化仿真
- 仿真建图 + PPT 制作
- 网上 URDF 模型导入与优化（如轮子模型重构为函数调用 + 参数化）

### 四、项目四：城市道路识别比赛（25:24–34:40）

**项目背景** [25:41–25:56]：参与城市道路识别比赛，控制小车沿地图行驶并对交通标识做出反应。小车由树莓派（上位机）+ 底盘（下位机）+ 摄像头 + 显示器组成。

**系统设计**：
1. **双摄像头** [26:14–26:20]：一只摄像头拍摄地面道路边线（巡线），另一只拍摄前方交通标识（识别）。
2. **模型训练** [26:28–26:28]：先使用小车底层驱动采集图像样本，训练识别模型。
3. **PID 自动巡线** [27:48–28:04]：识别道路边线后计算小车距道路中心的偏移量，通过 PID 控制器校正方向，使小车尽量沿道路中间行驶。
4. **交通标识识别** [28:04–28:27]：基于 YOLOv5 算法进行深度训练，识别出标识后做出相应反应（如人行道减速等）。
5. **演示视频** [28:27–28:38]：展示人行道标识识别效果。

**当前局限**：
- 道路边线在复杂场景下识别效果不佳，只能处理简单边线 [27:38, 30:52]
- 受光线影响大，团队重新拍摄样本集准备再次训练 [31:24–31:29]

**教师反馈** [32:11–33:22]：
- 目前摄像头仅做局部帧识别，未结合全局地图定位
- 建议引入全局定位信息或预设里程预测作为视觉失效时的备份策略（如起始位置固定，可估算何时该转弯）
- 团队表示后续会考虑在识别不可靠时结合全局信息做判断

### 五、项目五：迷宫导航（34:58–41:50）

**项目概述** [35:30–35:42]：在 Gazebo 中搭建迷宫地图，通过 SLAM 实现建图与导航。

**地图构建过程**：
1. **绘图方式选择** [36:12–36:42]：最初尝试 AI 辅助生成 `.world` 文件，但 AI 生成的墙体出现错位（墙对不齐）。最终放弃 AI，改用 Building Editor 工具手绘地图。
2. **文件格式** [36:50–37:04]：Building Editor 只能导出 CF 格式，无法直接在 Gazebo 中仿真。团队自行编写 `.world` 文件，在 `<include>` 中引用 SDF 模型，最终实现了迷宫仿真。

**实现流程** [37:24–37:52]：
- 编写两个 launch 文件：① 将小车加载到地图中；② 开启 SLAM 扫描运算
- 扫描完成后保存地图
- 基于已建地图进行路径规划，使小车走完迷宫

**演示** [38:00–41:50]：现场演示中扫描地图时因操作问题（走反方向）未完整扫描；通过展示录好的视频说明最终效果。

**分工**：
- 地图搭建与模型保留
- 地图设计 + SDF 文件编写 + PPT 制作与加工

### 六、项目六：扫地机器人全覆盖路径规划（41:50–50:47）

**项目概述** [42:31–43:06]：基于 ROS2 搭建仿真扫地机器人系统，实现自主清扫的核心功能。分工为三个模块：环境搭建与 SLAM（A）、全覆盖路径规划（B）、导航栈配置与系统集成（C）。

**模块 A：仿真环境与 SLAM 建图** [42:37–44:52]：
- 使用 Building Editor 绘制 10m×8m 居家户型（客厅、卧室、餐厅、书房、中央过道五个区域），插入家具并调整比例
- 雷达参数：Samples 从 0.01 修改为 0.03，提升环境感知精度与障碍物分辨率
- SLAM 建图使用 gmapping 算法：启动 Gazebo 环境 → 键盘控制机器人遍历全屋 → 实时构建栅格地图 → 保存地图文件
- 结果：墙体边界清晰完整，无漂移重影

**模块 B：全覆盖路径规划** [45:46–46:50]：
- 策略：**工字型（弓形）路径**，沿一个方向扫完一行后折返，来回往复直至覆盖全区域
- 实现：基于 ROS costmap 将环境离散化为栅格，识别自由空间与障碍物；奇数行从左到右、偶数行从右到左，记录所有自由栅格坐标形成路径序列，最终清扫覆盖率 >80%
- 结合模块 C 实现按房间分区清扫（扫完一个房间再进入下一个）[47:04]

**模块 C：导航栈配置与系统集成** [47:49–49:06]：
- 三层架构：**全局规划器**（基于 A* 算法，使用 ROS navigation stack 默认实现）→ **局部规划器**（TebLocalPlanner）→ **任务控制层**（自定义任务节点）
- 使用 costmap 防止机器人撞入障碍物
- 编写一键启动 launch 文件，一条命令同时启动 Gazebo 仿真环境、地图服务器、导航栈与任务控制

**现存问题** [49:50–50:15]：
- 墙角附近偶有卡顿抖动
- 局部路径规划中机器人偶发彻底卡住——团队编写了长时间停滞检测与重试机制

**教师点评** [50:15–50:29]：肯定每人分别介绍自己模块的方式，信息明确。强调仍需补充每人贡献度百分比。
