### 三、ROS核心概念

**什么是ROS？**
- 官方定义：适用于机器人的**开源元操作系统**
- "机器人"是广义概念：轮式移动机器人、无人机、水下机器人、无人驾驶汽车等
- 开源：源代码开放，软件完全免费

**Meta-OS（元操作系统）的定位**
```
上层应用软件
        ↑
┌───────────────┐
│  ROS (元操作系统)  │ ← 中间件/软件框架
│ - 硬件抽象       │
│ - 设备控制       │
│ - 消息传递       │
│ - 包管理        │
└───────────────┘
        ↑
┌───────────────┐
│  底层操作系统    │ ← Linux (主要) / Windows
└───────────────┘
        ↑
   计算机硬件
```

ROS不是传统意义上的操作系统（如Windows、Linux），而是：
- 运行于Linux之上的**软件包集合**
- 提供操作系统应有的服务（硬件抽象、设备控制、消息传递、包管理等）
- 介于底层操作系统与机器人应用之间的**中间件/软件框架**

### 四、ROS发展历史

```
2007年  斯坦福大学两名学生提出个人机器人项目(PR)，开始ROS雏形
   ↓
2008年  项目资源受限，Willow Garage公司接手维护
   ↓
2010年  ROS 1.0正式发布（以乌龟Box Turtle为标志）
   ↓
2012年  第一届ROSCon（ROS全球开发者大会）举办
   ↓
2013年  Willow Garage经营不善解散，OSRF（开源机器人基金会）接管
   ↓
2015年  发现ROS 1架构缺陷（单点故障问题），开始ROS 2设计
   ↓
2017年  ROS 2.0正式推出，架构全面重构
   ↓
2025年左右 ROS 1停止更新，社区全面切换到ROS 2
```

**ROS 1 vs ROS 2**
- ROS 1核心问题：基于Master主节点的架构存在**单点故障**——Master崩溃则整个系统崩溃
- ROS 2优势：重新设计架构，解决可靠性问题，支持多平台（Windows等）
- 本届是最后一届主要学习ROS 1的学生，下一届切换到ROS 2

### 五、ROS开发的初衷

**解决"重复发明轮子"问题**

在ROS出现之前，机器人开发面临的困境：
1. **硬件层面**：每个项目都要重新搭建硬件平台（结构、电机、驱动器、传感器等）
2. **软件层面**：
   - 传感器/执行器驱动程序无法复用
   - 不同模块间通信机制各异
   - 代码通用性差，他人难以接手
3. **时间分配**：大量时间浪费在底层基础设施，真正用于上层应用开发的时间很少

ROS的核心价值：
- 提供通用的硬件抽象层
- 标准化的节点间通信机制
- 丰富的开源软件包生态
- 让开发者专注于上层应用创新，而非重复造轮子

### 六、典型硬件平台

**PR2机器人（高端研究平台）**
- 2011年售价：**40万美元**
- 配置：2个7自由度机械臂、移动底盘、激光雷达、立体摄像头、IMU、触觉传感器
- 控制单元：2台8核电脑，运行Ubuntu + ROS
- 功能：叠衣服、做早饭、整理物品等（预设程序）

**TurtleBot（海龟机器人）**
- 定位：低成本ROS学习平台
- 价格：约几千元人民币（硬件全部开源）
- 特点：
  - 包含学习ROS所需的常用驱动器和传感器
  - 以树莓派作为主控板
  - 下学期实验课使用
  - 本学期可在仿真环境中使用
