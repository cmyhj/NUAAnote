## 要点详述

### 一、SLAM与导航实操要点

#### 1. 建图阶段
- **旋转操作技巧**：旋转时容易失控，建议转到目标角度后停掉再走直线，更加稳定 `[01:00-01:11]`
- **建图完成判断**：已知环境形状可直观判断；未知环境需判断依据 `[01:21-01:38]`
- **数据完整性重要性**：漏掉区域会导致SLAM构建的地图不准确，最好每个区域都过一遍 `[01:56-02:17]`

#### 2. 地图保存
- 地图文件包含：**图像文件 + `.yaml`配置文件**
- `.yaml`文件内容：地图路径、分辨率、方向等参数 `[05:08-05:20]`
- **考试提醒**：`.yaml`文件名及用途考试经常考到 `[04:54-05:12]`

#### 3. 导航操作流程
```
关闭之前进程 → 打开机器人+地图 → 运行导航节点 → 2D Pose Estimate初始定位 
→ 键盘控制移动使地图重合 → 关闭键盘（避免与导航冲突）→ 2D Nav Goal设置目标
```

**关键细节**：
- 初始定位时绿色点表示传感器估算的轮廓，与保存地图存在偏差 `[08:10-08:50]`
- 仅靠2D Pose Estimate不够，需**键盘控制机器人移动**收集环境信息，绿色点收缩表示定位精度提高 `[12:00-13:20]`
- 导航前必须**关闭键盘控制节点**：键盘持续发布命令会与导航算法冲突 `[13:28-13:50]`
- 设置导航目标时需拉出箭头，指定**到达后的朝向** `[13:57-14:14]`
- 路径是动态调整的：全局规划确定方向，局部规划实时避障 `[14:35-15:30]`
- 已知问题：某些算法规划路径时贴边过近，可能导致卡住 `[15:36-15:50]`

### 二、导航框架理论（考试重点）

#### 导航两大核心问题
1. **定位**：机器人在哪里？朝向如何？
2. **路径规划**：从当前位置到目标位置的路径

#### 两大功能包对比（必考，易混淆）

| 功能包 | 作用 | 英文含义误导 |
|--------|------|--------------|
| **`move_base`** | 路径规划 | 名字含"move"，容易误以为是移动控制 |
| **`AMCL`** | 自适应蒙特卡罗定位 | 非普通英文单词，难记忆 |

**考试提醒**：这两个功能包必考且容易混淆，建议考前突击记忆 `[17:22-18:05]`

#### move_base路径规划分层

```
┌─────────────────────────────────────────────────────────────┐
│                      move_base                               │
├───────────────────────┬─────────────────────────────────────┤
│    全局路径规划        │         局部路径规划                 │
│  (Global Planner)     │      (Local Planner)                 │
├───────────────────────┼─────────────────────────────────────┤
│ • 全局地图            │ • 局部代价地图(local costmap)        │
│ • 全局路径规划算法    │ • 本地路径规划算法                    │
│   (Dijkstra / A*)    │ • 动态避障、实时调整                  │
├───────────────────────┴─────────────────────────────────────┤
│  全局路径 → 提供给局部规划作为参考                            │
└─────────────────────────────────────────────────────────────┘
```

**类比理解** `[22:16-23:00]`：
- 全局规划：从家到新街口，先规划好大体方向（如坐地铁）
- 局部规划：中途发现地铁停运，临时改坐公交，但大方向仍往新街口

#### AMCL定位
- **全称**：Adaptive Monte Carlo Localization（自适应蒙特卡罗定位）`[24:24-24:45]`
- **方法**：概率统计方法，使用粒子滤波器跟踪机器人姿态 `[24:48-25:00]`
- **订阅数据**：scan（激光雷达）、tf（坐标变换）、map（地图）`[25:01-25:20]`

#### 里程计定位 vs AMCL定位

| 方式 | 使用信息 | 精度 |
|------|----------|------|
| 里程计定位 | 仅轮式里程计信息 | 不准确，有累积误差 |
| **AMCL定位** | 地图信息 + 里程计 + 激光雷达等所有传感器 | 更准确 |

**理解**：AMCL在map坐标系下估算机器人位置 `[27:10-27:25]`

### 三、ROS 2简介

#### ROS 1的历史局限
- 起源：2007年斯坦福，为PR2机器人开发 `[29:31-29:40]`
- PR2造价：约40万美元（2007年），工作站级硬件 `[31:17-31:40]`
- **遗留问题**：
  1. 未针对低端嵌入式优化，实时性难以保证 `[32:08-32:50]`
  2. 主要面向单机系统，无线/不稳定网络下不可靠 `[32:52-33:35]`
  3. 成本高，难以产品化 `[33:35-33:56]`

#### ROS 2推出时间线
- 2017年：ROS 2第一个稳定版本 `[29:46-29:55]`
- 2024年：第二个长期稳定版（课程采用版本）`[30:12-30:26]`
- 2025年：基于ROS 2的教材第二版 `[30:24-30:28]`

#### ROS 2六大特点

| 特点 | 说明 |
|------|------|
| **多机器人系统** | 提供多机器人协作的标准通信机制 |
| **跨平台** | 支持Linux、Windows、macOS、QNX，甚至无OS单片机 |
| **实时性** | 满足运动控制、动态避障的低延迟要求（如100ms内发现行人避障） |
| **网络连接** | WiFi等不稳定网络下保障数据完整性，支持加密 |
| **产品化** | 更强壮稳定，适合产业化应用 |
| **项目管理** | 全流程开发调试测试部署工具链 |

#### ROS 1 vs ROS 2 三大核心区别

| 维度 | ROS 1 | ROS 2 |
|------|-------|-------|
| **架构** | 有ROS Master（单点故障风险） | 无Master，分布式架构，Discovery自发现 |
| **通信协议** | TCP/UDP | **DDS**（数据分发服务） |
| **API设计** | 原有接口 | 采用C++新标准、Python 3特性，代码不直接兼容 |
| **编译系统** | catkin（大项目/Python项目问题多） | **ament_cmake + colcon** |

#### DDS通信详解 `[47:32-50:40]`
- DDS是物联网广泛应用的国际标准通信协议
- 解决ROS 1 TCP/UDP的问题：延迟、丢数据、无法加密
- **多厂商实现**：OpenSplice、FastRTPS等，性能/场景各有不同
- **rmw中间件（ROS Middleware）**：
  - 定义标准接口（收发数据、属性匹配等）
  - 各DDS厂商按标准写适配层
  - 用户无需关心底层DDS实现，使用统一ROS 2接口
