## 关键概念

| 概念 | 说明 |
|------|------|
| **Node（节点）** | ROS 中独立运行的进程，执行运算任务；相当于一个应用程序实例 |
| **Master / 节点管理器** | 负责节点注册、查找、建立连接；必须最先启动 |
| **[[ROS Topic（话题通信）|Topic（话题）]]** | 发布/订阅（Publish/Subscribe）通信模型，异步、灵活，支持一对多/多对多 |
| **Message（消息）** | 节点间传输的数据，严格数据结构，支持嵌套和自定义 |
| **[[ROS Service（服务通信）|Service（服务）]]** | 客户端/服务器（Client/Server）通信模型，同步请求-应答；只允许一个 server |
| **[[ROS Parameter Server（参数服务器）|Parameter Server（参数服务器）]]** | 全局参数存储，类似网络版全局变量 |
| **Package（功能包）** | ROS 软件基本组织单元，包含节点、库、配置文件等 |
| **package.xml** | 功能包清单，记录作者、许可、依赖等元信息 |
| **rqt_graph** | 可视化当前运行节点的关系图 |

## 要点详述

### 1. 课堂实操：三步启动 turtlesim

1. **启动 master（roscore）** — 必须先运行，否则其他节点无法通信
2. **启动 turtlesim 节点** — `rosrun turtlesim turtlesim_node`，每次随机显示不同样式的乌龟（对应不同 ROS 版本 logo）
3. **启动键盘控制节点** — `rosrun turtlesim turtle_teleop_key`，需保持键盘终端窗口处于**激活状态**才能捕获按键

> 快捷键：`Ctrl+C` 终止当前前台进程，等价于 Windows 任务管理器"结束任务"。

### 2. ROS 三种通信方式

| 通信方式 | 模型 | 同步/异步 | 特点 |
|---------|------|----------|------|
| **Topic** | Publish / Subscribe | 异步 | 一对多、多对一、多对多；发布者和订阅者互不知晓 |
| **Service** | Client / Server | 同步 | 一对多（一个 server，多个 client）；请求-应答 |
| **Parameter Server** | 全局键值存储 | — | 存储全局参数，节点通过网络读写 |

### 3. 计算图（Computation Graph）

由节点（Node）、话题（Topic）、服务（Service）等构成的运行时拓扑关系，用于描述程序如何运行。可使用 `rqt_graph` 自动生成可视化关系图，边上的标签即 topic 名称（如 `/turtle1/cmd_vel` 表示速度命令消息）。

### 4. 消息（Message）

- 严格数据结构：基础类型（int, float, bool 等）或复合类型（类似 C 语言 struct）
- 支持嵌套结构、数组及完全自定义数据类型
- 考试重点：如何自定义消息数据类型

### 5. 文件系统（File System）

- **Package（功能包）**：ROS 软件基本单元，包含节点代码、库、配置文件等
- **package.xml**：每个 package 必备清单文件，记录包名、作者、许可证、依赖等信息 — **考试常考**
- 功能包可包含多个节点

### 6. Master 的脆弱性

整个系统依赖 roscore 单点，若 master 崩溃或被杀死（如 Ctrl+C 误杀、黑客攻击），所有节点将无法找到彼此，整个系统瘫痪。
