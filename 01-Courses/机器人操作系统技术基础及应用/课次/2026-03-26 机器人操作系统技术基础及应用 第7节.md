## 关键概念

| 概念 | 说明 |
|------|------|
| **[[ROS Service（服务通信）|Service（服务）]]** | 客户端-服务器通信模型，客户端发请求带参数，服务端计算后返回应答 |
| **argc 判断** | 示例中判断 `argc != 3`，因 argv[0] 为程序名，实际传 2 个参数 |
| **CMakeLists.txt 配置** | 服务包需配置可执行文件、链接库、依赖关系（`add_executable`、`target_link_libraries`、`add_dependencies`） |
| **基础名称（Base Name）** | 无前缀，如 `base`；描述资源本身 |
| **全局名称（Global Name）** | 首字符 `/`，如 `/global/name`；解析度最高，全局可访问，但宜少用 |
| **相对名称（Relative Name）** | 由 ROS 根据默认命名空间补全前缀，提高移植性 |
| **命名规则** | 首字符：字母/波浪线/左斜杠；后续：字母/数字/下划线/斜杠；不可数字开头 |
| **环境变量** | `source` 后需重启终端或新开终端才能生效；用 `echo $ROS_PACKAGE_PATH` 检查 |

## 要点详述

### 1. 服务编程回顾

- 服务端代码：处理请求参数 → 运算 → 返回 `response`
- 客户端代码：从命令行读参 → 构造请求 → 发送 → 接收应答并显示
- 示例为加法服务，客户端传两个数，服务端返回和
- 与话题（Topic）区别：服务是**同步请求-应答**，话题是**异步发布-订阅**

### 2. 参数数量疑惑（argc == 3）

- 客户端判断 `argc != 3` 时报错
- 传参 `rosrun <pkg> <node> a b` 时，argv[0]=程序名, argv[1]=a, argv[2]=b —— 共 3 个
- 教师表示未完全搞懂，建议课后研究

### 3. 学生实操调试重点

- 建工作空间 → `mkdir -p ~/catkin_ws/src`
- 功能包必须放到 `src/` 目录下
- 编译：`cd ~/catkin_ws && catkin_make`
- 环境变量：`source devel/setup.bash`，且必须在新终端中生效
- 调试命令：`echo $ROS_PACKAGE_PATH`、`rospack find <pkg>`
- 运行：`roscore` → `rosrun <pkg> <server_node>` → `rosrun <pkg> <client_node> a b`

### 4. ROS 命名空间

- 计算图源（节点、话题、服务、参数）均需命名
- **基础名称**：纯名字，无前缀，如 `base`
- **全局名称**：以 `/` 开头，如 `/global/name`；绝对路径，解析度最高
- **相对名称**：不加 `/` 也不加 `~`，由 ROS 补全当前命名空间前缀
- **私有名称**：以 `~` 开头，解析时附加节点名作为命名空间
- **设计目的**：避免命名冲突，便于系统集成与模块复用
- **最佳实践**：尽量少用全局名称，多用相对/私有名称以提高移植性

> ⚠️ 命名规则是**考试重点**（选择题/判断题），需准确区分四种名称格式。
