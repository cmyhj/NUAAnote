## 关键概念

| 概念 | 说明 |
|------|------|
| **Publisher（发布者）** | 通过 `advertise` 向 Master 注册话题，循环 `publish` 发送消息 |
| **Subscriber（订阅者）** | 通过 `subscribe` 注册话题 + 回调函数，`ros::spin()` 等待消息 |
| **回调函数（Callback）** | 系统自动调用（非手动调用），消息到达时将消息指针作为参数传入 |
| **`std_msgs::String`** | 字符串消息类型，仅一个成员 `data`（std::string），需用 `.c_str()` 提取 C 风格字符串 |
| **`ros::spinOnce()`** | 执行一次回调处理，配合 `while` + `Rate` 用于发布者 |
| **`ros::spin()`** | 进入死循环（内部隐含循环），持续等待回调，用于订阅者 |
| **消息指针传递** | 订阅者回调参数为**常指针** `const ...::ConstPtr&`，通过 `->` 访问成员 |
| **CMakeLists.txt** | 配置头文件路径 (`include_directories`)、可执行文件 (`add_executable`)、链接库 (`target_link_libraries`)、依赖 (`add_dependencies`) |

## 要点详述

### 1. 发布者（Publisher）代码结构

```
头文件（ros/ros.h, std_msgs/String.h）
  → ros::init() 初始化节点（名称唯一）
  → NodeHandle 句柄
  → advertise 注册发布者（话题名称, 队列长度）
  → Rate 设置循环频率（如 10Hz = 100ms）
  → while (ros::ok()) {
       初始化消息（std_msgs::String, data 字段赋值）
       ROS_INFO 打印日志（终端显示）
       publisher.publish(msg)    // 真正发布消息
       ros::spinOnce()           // 处理一次回调
       rate.sleep()              // 休眠保证频率
       count++                   // 计数自增
    }
  → return 0
```

**关键区别**：
- `ROS_INFO`：仅终端打印日志，**不是**消息发布
- `publish()`：将消息发送给所有订阅该话题的节点
- `spinOnce()` 在发布者中**不能省略**（若发布者同时作为订阅者时需要）

### 2. 订阅者（Subscriber）代码结构

```
头文件（ros/ros.h, std_msgs/String.h）
  → 回调函数定义（接收消息指针，处理数据）
  → ros::init() 初始化节点
  → NodeHandle 句柄
  → subscribe 注册订阅者（话题名称, 队列长度, 回调函数名）
  → ros::spin() 进入等待循环（内部死循环）
```

**回调函数示例**：
```cpp
void chatterCallback(const std_msgs::String::ConstPtr& msg) {
    ROS_INFO("I heard: [%s]", msg->data.c_str());
}
```

- 回调函数名可自定义（不必须叫 `chatterCallback`）
- 系统在消息到达时**自动调用**，传入消息指针
- 指针传递避免数据拷贝和同步问题
- `.c_str()` 将 `std::string` 转为 `char*` 用于 `ROS_INFO` 格式化输出

### 3. `ros::spin()` 与 `while(ros::ok())` 的关系

| 模式 | 代码风格 | 适用场景 |
|------|----------|----------|
| `while(ros::ok()) { ... ros::spinOnce(); ... }` | 显式循环 | **发布者**（需要周期性执行发送逻辑） |
| `ros::spin()` | 隐式循环（内部死循环） | **订阅者**（只需等待回调，无周期性发送任务） |

`spin()` 内部实现本质上就是一个死循环 + `spinOnce()`，只是封装了起来。

### 4. CMakeLists.txt 编译配置（四项必须）

| 配置项 | 命令 | 作用 |
|--------|------|------|
| ① 头文件路径 | `include_directories(...)` | 设置头文件搜索路径，默认含功能包目录 + ROS 系统路径 |
| ② 可执行文件 | `add_executable(talker src/talker.cpp)` | 指定生成的可执行文件名与参与编译的源文件 |
| ③ 链接库 | `target_link_libraries(talker ${catkin_LIBRARIES})` | 链接系统/第三方库 |
| ④ 依赖 | `add_dependencies(talker ${PROJECT_NAME}_generate_messages_cpp)` | 处理消息等动态生成代码的依赖关系 |

- 头文件通常放在功能包根目录下的 `include/` 文件夹中
- 编译生成的二进制文件在 `devel/lib/<功能包名>/` 下
- 话题名称、队列长度等在发布者和订阅者之间必须一致
