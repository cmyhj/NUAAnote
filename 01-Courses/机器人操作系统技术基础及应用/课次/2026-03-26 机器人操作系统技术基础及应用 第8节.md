## 关键概念

| 概念 | 说明 |
|------|------|
| **全局名称 (Global)** | 以 `/` 开头，完整绝对路径，如 `/node1` |
| **相对名称 (Relative)** | 无 `/` 无 `~`，由 ROS 根据节点默认命名空间补全 |
| **私有名称 (Private)** | 以 `~` 开头，使用**节点全局名称**作为命名空间前缀 |
| **默认命名空间** | 解析相对名称时使用的基准路径 |
| **命名重映射 (Remapping)** | 节点启动时将内部资源名替换为新名称，`name:=new_name` |
| **ROS_MASTER_URI** | 多机通信时从机标记 master 位置的环境变量 |

## 要点详述

### 1. ROS 四种命名方式

- **基础名称**：不带任何斜杠或波浪线，就是一个名字
- **全局名称**：以 `/` 开头，完整路径，什么就是什么（送分题）
- **相对名称**：不以 `/` 开头，不完整；解析时 ROS 把节点的**命名空间**（不含节点自身）加到前面
  - 例：节点 `/wg/node1` 内出现 `name` → 解析为 `/wg/name`（注意不含 `node1`）
- **私有名称**：以 `~` 开头，只在本节点内部使用；解析时把**节点全局名称**整个替换 `~`
  - 例：节点 `/c1/private1` 内出现 `~max_vel` → 解析为 `/c1/private1/max_vel`

> ⚠ **易混淆点**：相对名称解析**去掉**节点自身，私有名称解析**保留并替换**节点自身。考试表格里的三种节点（根下的 node1、`/wg` 下的 node2、`/wg` 下的 node3）的解析对比需要熟练掌握。

### 2. 设置默认命名空间的三种方式

1. **命令行参数**：`__ns:=default_namespace`（双下划线）
2. **Launch 文件**：`ns="namespace"`
3. **环境变量**：`ROS_NAMESPACE`

> 允许同一份代码在不同命名空间下复用。

### 3. 命名重映射

- 语法：`name:=new_name`
- **先进行命名解析，再进行重映射**（顺序重要）
- 示例：`foo:=bar` 会把所有解析后为 `foo` 的名称替换为 `bar`
- 若 remap 参数含 `/`（如 `/foo:=bar`），则只匹配全局解析后等于 `/foo` 的名称
- 复杂情形（表格 5 种场景）需掌握：节点命名空间、remap 参数、匹配名称、解析后名称的推导

> 教师评注：第四个场景（`/wg` 命名空间 + `foo:=bar`）最难，remap 后的 `bar` 会再被相对解析一次。

### 4. 多机通信

- ROS 分布式的松耦合架构，一山不容二虎——**只能有一个 master**
- 配置步骤：
  1. **同一局域网**：`ifconfig`（Linux）/ `ipconfig`（Windows）查看 IP
  2. **修改 hosts 文件**：`/etc/hosts`，互相添加对方 IP 和主机名
  3. **测试连通**：`ping 主机名`
  4. **设置环境变量**（从机执行）：`export ROS_MASTER_URI=http://主机名:11311`
  5. **永久写入**：将上条命令加入 shell 配置文件（如 `~/.bashrc`）
- 验证：主机运行 `roscore` + `turtlesim`，从机发布速度指令让乌龟移动
