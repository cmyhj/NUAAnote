## 关键概念

- **列表的可变性 (mutable list)**：列表是有序序列，元素可增、删、改、排，原地修改后内存中的对象本身发生变化；字符串是有序序列但不可变，`s[0] = 'k'` 会直接报错，字符串类型也没有 insert 属性。
- **append 与 extend**：`append` 把参数当成**一个**元素加到末尾，即使参数是序列也不会展开；`extend` 则把序列中的元素逐个并入列表，等价于合并两个列表。
- **sort 与 sorted**：`a.sort()` 是列表的内嵌方法，直接改变 `a` 本身；`sorted(a)` 返回排好序的新列表，原列表保持不变。`sort(reverse=True)` 等价于先升序排好再反转。
- **元组 (tuple) 与打包/解包**：元组是与列表类似的有序序列，但不可直接修改、元素不可删除，只支持索引、切片、连接和"只读"方法。`a, b = b, a` 实质上先构造元组 $(b, a)$ 再解包赋给 $a, b$，即元组的打包 (packing) 与解包 (unpacking)。
- **单元素元组语法**：`(10,)` 才是元组，`(10)` 是整型。元组的判定标准是逗号而不是括号：`10,5` 无括号也是元组，`()` 是空元组，而 `(,)` 会报错（没有这种类型）。
- **可变数据类型与不可变数据类型**：可变的有列表、字典、集合、NumPy 数组和用户自定义对象；不可变的有整型、浮点型、长整型、字符串、元组以及不可变集合 (frozenset)。这是面试常考点。
- **引用、内存对象与垃圾回收 (garbage collection)**：赋值语句先让等号右边生成内存中的对象，变量再引用该对象。可变对象可在原地修改；对不可变对象"改值"实际是重新分配一块内存放新值，旧对象失去引用后被垃圾回收。
- **索引越界与切片越界**：列表、元组、字符串的**单个元素索引**不允许越界，会报错；但**切片**允许越界，超出范围时按边界截断，不报错。
- **字典 (dict) 与键值对 (key-value pair)**：用成对的大括号定义，类型名为 `dict`（dictionary 的缩写），也可用 `dict()` 构造空字典；数据以"键: 值"成对存放，通过键索引值、按键修改值。其他语言里的 HashMap、Map 对应 Python 的字典。

## 要点详述

### 一、回顾与列表元素的添加（04:22-09:04）

上节已讲过列表与字符串的共性（都能索引和切片）与差异（列表支持修改，字符串不支持）。本节接着讲元素的添加。老师用图像数据预处理举例：训练集文件夹里可能有一万张图片，尺寸各异（如 $700\times600$、$720\times540$，也有到 1080 的），测试集同样如此，但 CNN 之类网络往往要求统一输入尺寸（例如 YOLO 系列常用 $448\times448$ 一类固定分辨率，分类网络则常用 $224\times224$）。于是典型流程是：定义一个空列表 → 根据图像路径遍历目录取出图像列表 → 逐张统一尺寸 → 把处理结果 append 到新列表，得到格式统一的新数据集。

- `append`：每次只添加**一个**元素。`a = [1,2,3,4,5]` 时 `a.append(10)` 得到 `[1,2,3,4,5,10]`；再 `a.append([11,12])`，结果是末尾多出 `[11,12]` 这个嵌套列表本身，而不是把它展开成 11 和 12。
- `extend`：把另一个序列的元素逐个并进来。例如对 `[1,2,3,4]` 执行 extend 后得到类似 `1,2,3,4,6,7,...` 的合并结果。

### 二、列表的插入、删除与排序（09:04-13:19）

- **insert**：按下标插入，插入点之后的元素依次后移。对 `[1,2,3,4]` 在下标 3 处插入字符 `a`，列表变为 `[1,2,3,'a',4]`。
- **remove**：移除**第一个出现**的匹配对象；若该元素不在列表中则报错。`[11,1,2,3,4]` 执行 remove 后得 `[1,2,3,4]`。
- **pop**：弹出元素并**返回被弹出的值**，参数是索引（这与 remove 按值删除不同）。
- **sort**：内嵌方法，直接原地改变列表，例如把 `[11,11,13,10,12]` 排成升序。列表是有序序列，元素位置一旦改变就被视为一个新的列表，所以原地排序会改变原数据。
- **sorted**：不想改动原列表时用 `sorted(a)`，`a` 保持不变，升序结果放到新变量里。
- **reverse**：反向排列，`a.reverse()` 把 `[1,2,3,4,5,6]` 变成 `[6,5,4,3,2,1]`。若不希望改变原列表，可用反向切片实现同样效果（`a` 不变，`b` 变成逆序）。
- **help**：Python 内置帮助。对某个方法不清楚，可以写 `help(a.sort)` 或直接在方法后加问号，运行后日志里会打印该函数的参数说明——例如 `sort` 有一个 `reverse` 参数，默认 `False` 表示从小到大；写成 `reverse=True` 就是从大到小排，实质是"先升序排好再反转"。

### 三、列表与字符串的可变性对比（13:19-16:11）

列表显而易见是可变的：可以按索引改值、可以 insert 插值（如把第一个元素改成 100，同时在下标 3 处插入 200，原下标 3 的元素后移）。字符串则不可变：

- 用 `s[0] = 'k'` 试图把 `hello world` 的 h 改成 k 会报错。
- 字符串不支持 `insert`，直接提示字符串类型没有 insert 属性。
- 字符串方法只**返回新字符串**，不改变原先的值。想替换字符要调用 `replace`，例如把 world 换成更短的名字，但 `s` 本身仍是 `hello world`，只有把返回值重新赋给 `s`，`s` 才真正改变。

由此老师给出本节的面试高频考点——**Python 的可变数据类型与不可变数据类型**：

- 可变：列表、字典、集合，以及 NumPy 数组、用户自定义对象；
- 不可变：整型、浮点型、长整型、字符串、元组，以及不可变集合。

### 四、元组：定义、语法陷阱与打包解包（16:11-28:08）

**定义**：元组与列表类似，是元素的有序序列；区别是元组不可以直接修改，元组中的元素也不可以被删除，但可以被索引、切片和连接。语法一般用小括号把元素括起来，元素之间用逗号隔开；索引、切片与列表完全一致，元素类型不要求一致，还允许列表与元组互相嵌套。

**元组元素的对应赋值（解包）**：把一个三元组赋给三个变量，例如 `x, y, z = (1, 2, 3)`，就得到 $x=1,\ y=2,\ z=3$；已定义好的元组本身不可修改。

**追问与答案**：既然元组和列表唯一的差别只是"能不能改"，那我只要不修改列表不就行了，为什么还要用元组？老师的答案是元组的打包与解包能力。经典的变量交换：

- 传统写法需要引入临时变量（比喻成交换两杯饮料要借一个空杯子）：`c = a`、`a = b`、`b = c`，三行代码；
- 用元组一行搞定：`a, b = b, a`。这一行先把右边的 $b, a$ 打包成一个元组，再解包赋回 $a$ 和 $b$，所以 $a$ 变成原来的 $b$、$b$ 变成原来的 $a$。

**课堂互动：x1~x5 是什么类型**。老师给出五个表达式并请同学举手判断，随后现场用代码验证：

| 表达式 | 类型 | 原因 |
|--------|------|------|
| `x1 = 10` | 整型 int | 小括号里一个数、没有逗号，仍是整型 |
| `x2 = ()` | 空元组 tuple | 单独一个小括号、里面没有元素也是元组 |
| `x3 = (10,)` | 元组 tuple | 一个元素加逗号，逗号才是元组的关键 |
| `x4 = 10,5` | 元组 tuple | 没有小括号，但用逗号隔开就是元组 |
| `x5 = (,)` | 报错 | 没有这种类型，只留一个逗号也会报错 |

结论：**有括号的不一定是元组，没有括号并且没有逗号的也不一定是整型**。老师因此强调：为避免编程中不必要的麻烦和误判，定义元组时统一加小括号，这是最简单、最稳妥的写法。

### 五、元组的实战价值：颜色、多返回值与嵌套（28:08-36:22）

**图像处理中的颜色元组**：做视觉项目时经常要在图上给目标画矩形框并指定框的颜色，这个颜色值就是一个元组。以三通道亮度组合表示颜色：$R$ 最高、$G$ 与 $B$ 为 0 时是红色 $(255,0,0)$；$(0,255,0)$ 是绿色；$(0,0,255)$ 是蓝色；三个通道取不同值组合出其他颜色（例如 $(255,0,255)$ 是品红）。用元组传颜色是因为这些值必须固定、不应被修改。OpenCV、matplotlib、PIL 等库在传颜色时都采用这种形式。

**函数返回多个值**：交换功能的函数化写法：

```python
def change(a, b):
    a, b = b, a
    return a, b
```

`return a, b` 返回的就是一个元组。如果不用元组，很多同学会另外定义一个空列表，把 a、b 分别 append 进去再 return，返回值是一个含两个元素的 list——远不如直接 return 元组简洁。这也解释了为什么 OpenCV 和很多图像处理算法的返回值是多个：**返回值很多个时，它以元组格式返回**。

**列表与元组的嵌套**：

- 列表套列表：大列表里放多个小列表，索引从左往右、由外向内，`list1[0][0]` 取出第一个子列表的第一个元素。
- 列表套元组：列表里也可以放元组，甚至列表与元组混合。
- 元组套列表：元组的一维索引取到内层列表，再对该列表做二维索引，例如取第 3 个元素（内层列表），再取它的下标 1。
- 可变性规则：元组本身不可修改，但若元组中嵌套的是**列表**，那么这个列表内的元素**可以**被修改（例如把内层列表的 6 改成 9）。这与"元组不可变"并不矛盾——不可变的是元组的元素指向本身（不能用元组下标把整个列表换掉），但那个列表对象内部的元素仍可改。
- 元组套元组：里外都不可修改。

### 六、可变对象、不可变对象与内存模型（36:41-40:04）

Python 中一切数值、字符串、列表、元组都是对象。变量用赋值语句创建后，等号右边的值成为内存中的一个对象，变量去**引用**这个对象，这就涉及 Python 的垃圾回收机制。

- 不可变对象：执行 `n = 5` 时，内存中为 5 分配一块区域，`n` 指向它；这个 5 不能再被原地改。要变成 7，就必须在内存里另找一块地方放 7，让 `n` 指过去，原来的 5 被抛弃、交给垃圾回收。元组同理：`x = (1, 2)` 后想改成 `(3, 4)`，只能重新分配一块内存放 3 和 4 再指向 `x`，1 和 2 那份被回收。
- 可变对象：列表在内存中的组织方式允许直接更新其内部元素的内存地址，即在原地修改值，不需要整体搬家。

**索引与切片的越界规则**：Python 中列表和元组**单个元素**的索引不允许越界（字符串也一样），但**切片**允许越界，越界部分按边界截断。

### 七、元组操作的代码演示与结论（40:05-43:49）

课上现场演示：定义一个元素全为整数的元组，方便观察索引与切片——直接用下标索引取值，用切片取子序列；用"单个元素加逗号"的方式构造单元素元组（`(10,)` 或省略括号的 `10,`）；用 `tuple()` 把列表强制转换成元组；再用 `count` 统计某元素出现个数、用 `index` 找某个值所在的位置。

小结：元组的操作与列表几乎如出一辙，唯一不同就是**元组不能被修改**，因此只能保留不可变类的方法（如计数、查位置）。元组的定义形式很多，但为了不给自己找麻烦，统一用小括号括起来。

### 八、字典：为什么需要键值对（43:49-51:16）

老师用超市扫码引出字典：收银员扫商品条形码，扫到的只是编号，却能同时查到它是什么物品、价格多少、属于什么类别、进货日期、库存量等信息。原因是这些信息以**字典格式**存储——键是条形码编号，值是一个包含各种属性的结构。

反例说明为什么列表不够用：把一个物品的信息（它是什么、类别、数量、生产日期）单纯塞进一个列表或元组，事后找元素时根本分不清哪个位置是什么含义，也不知道 100 是价格还是数量。所以需要一种把"属性的描述"和"它对应的值"绑在一起存储的结构，这就是字典。在其他语言里，C、Java 中对应的是哈希表、HashMap 或 Map 这类结构。

- **定义**：用成对的大括号定义，类型名 `dict`（dictionary 的缩写）；也可以用内置函数 `dict()` 定义空字典。
- **索引与更新**：通过键索引值（`a['first']` 之类），也通过键修改值——列表、元组、字符串都是按索引改值，字典是按**键**改值。例如把某个键原来的值 1 改成 3，另一个键的值保持不变。
- **初始化**：也可以在小括号里写键值对的形式初始化，键不局限于字符串，也可以是整型（如用 3 作键）。
- **易错点**：整型 3 和加双引号的 `'3'` 完全是两个量，一个是整型、一个是字符串，两者不能画等号，用 `'3'` 去索引整型键 3 会报错。
- **为什么不用数字顺序索引**：Python 不支持用数字按下标顺序查看字典中的值，而且数字本身也可能成为键，会引起混乱，所以字典一律通过键索引。若写 `a[0]`，会直接报错。
