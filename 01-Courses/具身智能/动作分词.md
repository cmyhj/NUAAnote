# 动作分词（Action Tokenization）详解

## 一、为什么需要动作分词？

### 核心矛盾

VLM（如 PaliGemma）本质上是一个**语言模型**，它的输出是离散的 token（词元）。但机器人动作是**连续的、高维的数值信号**。

```
语言模型输出:  "the" "cat" "sat" ...    → 离散词元 ✅
机器人动作:    [0.23, -0.51, 0.78, ...] → 连续浮点 ❓
```

**动作分词的目的**：建立一座桥梁，让语言模型能够用它熟悉的方式（预测下一个 token）来生成机器人动作。

## 三、动作分词器的训练（离线阶段）

### 3.1 数据准备

首先，需要大量机器人执行任务的动作数据：

```
数据集示例:
  轨迹 1: [a₁, a₂, a₃, ..., a_T]   // T步动作序列
  轨迹 2: [a₁, a₂, a₃, ..., a_T]
  ...

每步动作: aᵢ ∈ ℝ^D   // 例如 D=7 (7个关节角度) 或 D=24 (全身控制)
```

### 3.2 Action Chunk 切分

将连续动作序列切分为固定长度的 **action chunk**：

```
原始序列: [a₁, a₂, a₃, a₄, a₅, a₆, a₇, a₈, a₉, a₁₀, ...]
                  ↓ 切分为 chunk (H=4)
Chunk 1:  [a₁, a₂, a₃, a₄]     → 展平为 x₁ ∈ ℝ^(4×D)
Chunk 2:  [a₃, a₄, a₅, a₆]     → 有重叠，滑动窗口
Chunk 3:  [a₅, a₆, a₇, a₈]
...
```

每个 chunk 展平为一个高维向量：

$$x_i = [a_1, a_2, ..., a_H] \in \mathbb{R}^{H \times D}$$

### 3.3 VQ-VAE 训练（向量量化变分自编码器）

这是动作分词器的核心。VQ-VAE 学习将连续的 action chunk **压缩为离散的 token ID**。

```
┌─────────────────────────────────────────────────┐
│              VQ-VAE 动作分词器                    │
│                                                 │
│  编码:                                          │
│  ┌──────┐    ┌────────┐    ┌──────────────┐    │
│  │ x    │───→│Encoder │───→│ z_e ∈ ℝ^d    │    │
│  │(H×D) │    │ (CNN/  │    │ (连续隐变量)  │    │
│  └──────┘    │  MLP)  │    └──────┬───────┘    │
│              └────────┘           │             │
│                                   ▼             │
│                          ┌───────────────┐      │
│                          │ 向量量化       │      │
│                          │ 找最近的码本向量│      │
│                          │ codebook[e_k] │      │
│                          └───────┬───────┘      │
│                                  │              │
│                     输出: token ID k            │
│                                  │              │
│  解码:                           ▼              │
│  ┌──────────────┐    ┌────────┐    ┌──────┐    │
│  │ x̂ ≈ x       │←───│Decoder │←───│ z_q  │    │
│  │(重构动作)     │    │ (MLP)  │    │      │    │
│  └──────────────┘    └────────┘    └──────┘    │
└─────────────────────────────────────────────────┘
```

#### 向量量化过程的数学表达

**Step 1: 编码**

$$z_e = \text{Encoder}(x), \quad z_e \in \mathbb{R}^d$$

**Step 2: 量化（Quantization）**

维护一个**码本（Codebook）** $\mathcal{C} = \{e_1, e_2, ..., e_K\}$，其中每个 $e_k \in \mathbb{R}^d$ 是一个可学习的向量。

$$k^* = \arg\min_{k \in \{1,...,K\}} \|z_e - e_k\|^2$$

$$z_q = e_{k^*}$$

**输出**：离散的 token ID $k^*$

**Step 3: 解码**

$$\hat{x} = \text{Decoder}(z_q)$$

**Step 4: 训练损失**

$$\mathcal{L}_{\text{VQ}} = \underbrace{\|x - \hat{x}\|^2}_{\text{重构损失}} + \underbrace{\|\text{sg}[z_e] - z_q\|^2}_{\text{码本损失}} + \underbrace{\beta \|z_e - \text{sg}[z_q]\|^2}_{\text{承诺损失}}$$

其中 $\text{sg}[\cdot]$ 表示 stop gradient（截断梯度）。

---

### 3.4 直观例子

```
码本大小 K = 1024 个"动作词"

码本（部分）:
  Token 0  : [0.12, -0.34, ...]  → 对应"向左移动一小步"
  Token 1  : [0.45,  0.67, ...]  → 对应"张开夹爪"
  Token 2  : [-0.21, 0.89, ...]  → 对应"快速向前伸展"
  ...
  Token 1023: [0.03, -0.12, ...]  → 对应"缓慢旋转"

给定一个动作 chunk: x = [a₁, a₂, a₃, a₄]（4步抓取动作）
  ↓ 编码器
  z_e = [0.44, 0.68, ...]
  ↓ 量化（找最近码本向量）
  最近的是 Token 1: [0.45, 0.67, ...]
  ↓ 输出
  token_id = 1 （"张开夹爪"语义）
```

## 四、VLM 如何使用动作 Token

### 4.1 预训练阶段：自回归预测动作 Token

训练好 VQ-VAE 后，用它把数据集中所有动作 chunk 转为 token，然后训练 VLM 像预测文字一样预测动作 token。

```
训练样本构造:

输入序列:
  <image encoding> "把红色方块放到蓝色方块上" <action> token_23 token_47 token_12

目标序列（右移一位）:
  "把红色方块放到蓝色方块上" <action> token_23 token_47 token_12 token_89

损失: CrossEntropy(predicted_token, ground_truth_token)
```

VLM 学会了：**看到图像 + 语言指令 → 输出一串动作 token 序列**

### 4.2 推理阶段

```
输入: 图像 + "把红色方块放到蓝色方块上"

VLM 自回归生成:
  Step 1: → token_23  (移动到方块上方)
  Step 2: → token_47  (下降接近)
  Step 3: → token_12  (闭合夹爪)
  Step 4: → token_89  (抬起)
  Step 5: → <eos>     (动作序列结束)

将 token 序列 [23, 47, 12, 89] 送入 VQ-VAE 解码器
→ 解码为连续动作 [a₁, a₂, ..., aₙ]
→ 机器人执行
```

## 五、离散分词 vs 连续 Flow Matching

π0 的一个关键设计是**同时支持两种动作生成路径**：

| 特性 | 离散动作分词 | Flow Matching 动作头 |
|------|------------|-------------------|
| **输出类型** | 离散 token ID | 连续向量 $x_1 \in \mathbb{R}^{H \times D}$ |
| **生成方式** | 自回归逐 token 预测 | ODE 一次积分生成整个 chunk |
| **训练阶段** | 预训练（多机器人、多任务数据） | 微调（特定任务数据） |
| **优势** | 与 VLM 天然兼容，易于大规模预训练 | 动作质量更高，精度更好 |
| **劣势** | 离散化有精度损失 | 需要额外的去噪过程 |

### π0 的实际做法

```
预训练阶段 (多样数据):
  VLM 主干 + 离散动作分词头
  目的: 学习通用的"视觉-语言→动作"映射
  数据: 来自多种机器人的海量数据

微调阶段 (特定任务):
  VLM 主干 + Flow Matching 动作头
  目的: 精细化生成高质量动作
  数据: 特定机器人的任务数据
```

## 六、码本大小的选择

| 码本大小 $K$ | 粒度 | 类比 | 适用场景 |
|------------|------|------|---------|
| 64 | 粗粒度 | 基础词汇量 | 简单任务，如二值开关 |
| 256 | 中等 | 常用词典 | 桌面操作 |
| 1024 | 细粒度 | 丰富词典 | π0 采用，平衡精度与规模 |
| 4096+ | 极细 | 大型百科全书 | 高精度需求，但训练难度增大 |

码本越大，量化误差越小，但 VLM 预测的难度越大（词汇表越大，分类越难）。

## 七、总结

动作分词的本质可以类比为：

> **给机器人编写一本"动作字典"，然后让大语言模型学会用这本字典"造句"来表达复杂的动作序列。**

```
自然语言:  词 → 词表 (50000个词) → 句子
动作分词:  chunk → 码本 (1024个动作词) → 动作序列

VLM 的统一能力:
  看到图像 + 读到指令 → 预测动作token序列 → 解码为机器人动作
```
