# 第7章 ROS2 简介

## 学习目标

- 理解 ROS1 的局限性及其历史背景
- 掌握 ROS2 相比 ROS1 的核心变化
- 理解 DDS 去中心化通信架构
- 了解 QoS 服务质量策略
- 熟悉 ROS1 与 ROS2 的命令对比

---

## 7.1 为什么需要 ROS2

### 7.1.1 ROS1 的历史局限

ROS1 最初为 **PR2 机器人**设计。PR2 的工作条件非常理想：

- 独立工作（单机器人，不需要与其他机器人协作）
- 工作站级算力（不需要考虑嵌入式资源有限的情况）
- 有线网络连接（不需要应对不可靠的无线通信）
- 学术研究（不需要满足产品级稳定性要求）

### 7.1.2 ROS1 的三大核心问题

随着 ROS 应用的扩展，原有架构暴露出三个主要问题：

| 问题 | 说明 |
|------|------|
| **单点故障** | Master 是系统的唯一协调者，一旦崩溃整个系统失去注册与发现能力（新节点无法加入） |
| **无实时性支持** | 基于 TCP 的通信无法保证实时性能，无法满足工业控制和自动驾驶场景 |
| **安全性缺失** | 没有内置加密或认证机制，不适合商业产品和敏感应用 |

此外，资源有限的嵌入式系统、不可靠的无线网络、跨平台需求（Windows/Mac/Linux）等场景 ROS1 也难以胜任。

## 7.2 ROS2 的核心变化

### 7.2.1 DDS —— 去中心化通信

ROS2 最大的架构变化：**底层通信从自定义的 TCPROS 改为 DDS（Data Distribution Service）**。

| 对比维度 | ROS1 | ROS2 |
|----------|------|------|
| 通信协议 | 自定义 TCPROS/UDPROS | **DDS** 工业标准中间件 |
| 节点发现 | 依赖 Master 中心注册 | **自动发现**（去中心化） |
| 单点故障 | **存在**（Master 崩溃→系统瘫痪） | **消除**（无中心节点） |
| 实时性 | 无实时支持 | 支持实时通信 |
| 跨平台 | 主要 Linux（Ubuntu） | Linux / Windows / macOS / RTOS / MCU |

DDS 的特点：
- **自动发现**：节点无需注册到中心即可互相感知
- **发布-订阅和请求-响应**多种通信模式
- **QoS** 服务质量策略

### 7.2.2 QoS —— 服务质量策略

DDS 引入了 QoS（Quality of Service），允许开发者为每个话题通信配置策略参数：

| QoS 策略 | 选项 | 适用场景 |
|----------|------|----------|
| **可靠性** | RELIABLE（保证送达） | 关键指令、配置更新 |
| | BEST_EFFORT（尽力送达） | 传感器数据流（低延迟优先） |
| **持久性** | VOLATILE（不保存） | 实时数据 |
| | TRANSIENT_LOCAL（保留最近数据） | 新节点需要获取最新状态 |
| **历史记录** | KEEP_LAST(N) | 只保留最近 N 条 |
| | KEEP_ALL | 保留所有 |

### 7.2.3 rmw —— 中间件抽象层

ROS2 在应用层与具体 DDS 实现之间增加了**rmw（ROS Middleware Wrapper）**抽象层，屏蔽不同 DDS 厂商实现的差异。开发者无需关注底层用的是哪个 DDS。

```
┌──────────────┐
│   ROS2 应用   │  (rclcpp / rclpy)
├──────────────┤
│     rmw      │  中间件抽象层
├──────────────┤
│     DDS      │  (FastDDS / CycloneDDS / Connext 等)
└──────────────┘
```

### 7.2.4 ROS2 的核心目标

| 目标 | 说明 |
|------|------|
| 多机器人系统 | 提供标准的多机器人通信方法和协作机制 |
| 跨平台 | 支持 Linux、Windows、macOS、RTOS、MCU |
| 实时性 | 满足工业控制和自动驾驶的实时需求 |
| 产品化 | 持续稳定的产品级系统 |

## 7.3 ROS1 vs ROS2 快速对比

| 方面 | ROS1 | ROS2 |
|------|------|------|
| Master | 必需（`roscore`） | **无**（DDS 自动发现） |
| 通信 | TCPROS/UDPROS | DDS |
| 编译 | `catkin_make` | `colcon build` |
| 运行节点 | `rosrun pkg node` | `ros2 run pkg node` |
| 查看话题 | `rostopic list` | `ros2 topic list` |
| 查看节点 | `rosnode list` | `ros2 node list` |
| C++ API | `roscpp` | `rclcpp` |
| Python API | `rospy` | `rclpy` |
| 消息定义 | `.msg` / `.srv` | `.msg` / `.srv`（复用） |
| 平台 | Ubuntu Linux | Linux / Windows / macOS |
| Python | 2.7（旧版）/ 3.x | 3.x 起 |
| launch | XML `.launch` | Python `.launch.py` / XML / YAML |

## 本章小结

1. ROS1 三大问题：**单点故障、无实时性、无安全性**
2. ROS2 核心变化：**DDS 替代 Master**，实现去中心化、自动发现
3. **QoS** 服务质量策略：可靠性、持久性、历史记录等可配置
4. **rmw** 中间件抽象层屏蔽不同 DDS 实现
5. ROS2 命令：`ros2 run`、`ros2 topic`、`colcon build`
6. ROS1 与 ROS2 的核心概念（节点、话题、服务）保持一致，降低了迁移成本
