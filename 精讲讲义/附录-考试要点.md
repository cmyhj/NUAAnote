## 一、必考概念速查（名词解释）

| 术语                  | 一句话定义                                        |
| ------------------- | -------------------------------------------- |
| **ROS**             | 运行在 Linux 之上的开源元操作系统（中间件/软件框架）               |
| **Node（节点）**        | 执行运算任务的最小进程单元，计算图的基本元素                       |
| **Master（节点管理器）**   | 节点注册与匹配中心，通过 `roscore` 启动，位于应用层              |
| **Topic（话题）**       | 基于发布-订阅模型的异步通信方式，7 步建立连接                     |
| **Service（服务）**     | 基于客户端-服务器模型的同步通信方式，5 步建立连接                   |
| **Message（消息）**     | 节点间通信的严格类型化数据载体                              |
| **Parameter（参数）**   | 全局 Key-Value 配置字典，由 Master 管理，3 步全 RPC       |
| **Workspace（工作空间）** | src/build/devel/install 四目录结构                |
| **Package（功能包）**    | ROS 软件基本单元，至少包含 package.xml 和 CMakeLists.txt |
| **Overlay（工作空间覆盖）** | 同名包覆盖机制，ROS_PACKAGE_PATH 从前往后查找              |
| **Namespace（命名空间）** | 全局（/）、相对、私有（~）、基础 四种命名方式                     |
| **URDF**            | 统一机器人描述格式，XML 描述 link + joint                |
| **XACRO**           | URDF 的宏扩展，支持变量、模板、文件引用                       |
| **TF**              | 坐标系变换广播-监听系统，树形结构管理                          |
| **SLAM**            | 同时定位与建图                                      |
| **DDS**             | ROS2 的去中心化通信中间件，替代 Master                    |
| **QoS**             | 服务质量策略（可靠性、持久性、历史记录等）                        |
| **LTS**             | 长期支持版（5 年），偶数年发布                             |

### 2.3.2 功能包清单（package.xml)

包含功能包的元信息：名称、版本号、作者信息、许可信息、编译依赖（`<build_depend>`）和运行依赖（`<run_depend>`）。

### 2.3.3 元功能包（Meta Package）

将多个功能包整合为一个逻辑独立的功能包。只需要一个特殊的 `package.xml`（含 `<metapackage/>` 标签），不需要 `<build_depend>`。
### 2.1 三大通信机制的步骤数

| 机制 | 步骤数 | 协议分布 |
|------|--------|----------|
| 话题通信（Topic） | **7 步** | 前 5 步 RPC + 后 2 步 TCP |
| 服务通信（Service） | **5 步** | 比话题少 2 个 RPC 步骤 |
| 参数管理（Parameter） | **3 步** | 全 RPC，不涉及 TCP/UDP |

### 2.2 话题 vs 服务对比（必考）

| 对比维度 | 话题 | 服务 |
|----------|------|------|
| 通信模型 | 发布/订阅 | 客户端/服务器 |
| 同步性 | 异步 | 同步（请求后阻塞等待） |
| 是否有应答 | 无 | 有（Request → Response） |
| 是否有缓冲区 | 有 | 无 |
| 节点关系 | 多对多 | 一对多（一个 Server 多个 Client） |
| 适用场景 | 连续高频数据流 | 逻辑处理、参数查询 |

### 2.3 ROS1 三大局限性

1. **单点故障**：Master 崩溃 → 系统失去节点发现能力
2. **无实时性支持**：TCP 通信无法保证实时性能
3. **安全性缺失**：无内置加密和认证机制

### 2.4 ROS 五大特点

1. **点对点设计**：分布式网络，节点通过 TCP/IP 通信
2. **多语言支持**：C++、Python、Java 等，语言弱相关
3. **架构精简、集成度高**：模块化，统一消息接口
4. **组件化工具包丰富**：rviz、Gazebo、rqt 等
5. **免费并且开源**：BSD 许可证

### 2.5 架构三层

**从运行角度：**
```
应用层（Master + 用户节点）
  ↑
中间层（TCPROS/UDPROS + 机器人开发库）
  ↑
OS层（Linux Ubuntu）
```

**从系统实现角度：** 计算图、文件系统、开源社区

### 2.6 工作空间四目录

| 目录 | 名称 | 作用 |
|------|------|------|
| `src` | 代码空间 | 存放功能包源码 |
| `build` | 编译空间 | 编译中间文件（自动生成） |
| `devel` | 开发空间 | 可执行文件 + setup.bash |
| `install` | 安装空间 | 部署文件（可选） |

### 2.7 命名空间四种类型

| 类型 | 格式 | 节点 `/wg/node1` 内解析 |
|------|------|------------------------|
| 基础名称 | `name` | `/wg/name` |
| 全局名称 | `/global/name` | `/global/name` |
| 相对名称 | `relative/name` | `/wg/relative/name` |
| 私有名称 | `~private/name` | `/wg/node1/private/name` |

## 六、编程模板速查

### Publisher

```cpp
ros::init(argc,argv,"name");
ros::NodeHandler n;
ros::Publisher chatter_pub = n.advertise<std_msgs::String>("chatter",1000);

ros::Rate loop_rate(10);
int count=0;

while(ros::ok())
{
	std_msgs::String msg;
	std::stringstream ss;
	ss << "hello world" << count;
	msg.data = ss.str();
	
	ROS_INFO("%s",msg.data.c_str());
	chatter_pub.publish(msg);
	
	ros::spinOnce();
	loop_rate.sleep();
	++count;
}
```

### Subscriber

```cpp
void callback(const std_msgs::String::ConstPtr& msg) {
    ROS_INFO("I heard: [%s]", msg->data.c_str());
}
// main 中：
ros::Subscriber sub = n.subscribe("chatter", 1000, callback);
ros::spin();
```
